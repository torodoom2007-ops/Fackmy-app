# fackmy.IL — שדרוג פרויקט

## מה השתנה
- הוגדרו ברירת מחדל `role: "regular"`, `isPro: false`, `subscriptionStatus: "free"` בעת הרשמה רגילה ואנונימית.
- נוסף דף `premium.html` עם השוואת Regular/Pro, מחיר תצוגה של $3 לחודש, אנימציות, חותמת Pro וטופס הדגמה שאינו גובה כסף.
- נוספו קישורים לדף Pro מהפיד ומעמוד הפרופיל.
- נוספו תצוגות חותמת Pro לפרופילים כאשר שדה הסטטוס מתאים.
- נוספו בחירת תמונה שנייה, תצוגה מקדימה ודחיסת תמונות לפני שמירה.
- נוסף צ'קבוקס "זכור את הפרטים שלי" שמשתמש ב-Firebase Local/Session persistence.
- נוספה אפשרות למחיקת חשבון בסיסית עם אישור כפול.
- תוקנה הצגת תוכן הודעות בצ'אט כך שטקסט משתמש מוצג באמצעות `textContent` ולא מפורש כ-HTML.
- נוספה בדיקת UX למגבלת חמש שיחות חדשות למשתמש Regular.
- נוסף קובץ `firestore.rules` כנקודת התחלה להגנת מסמכים.

## בדיקות אבטחה שחייבים להשלים לפני פרסום
1. **אין לפרסם את האתר עם כללי Firestore פתוחים.** יש לפרוס ולבדוק את `firestore.rules` בסביבת בדיקה תחילה. כללי אבטחה עשויים לדרוש התאמות בהתאם לנתונים הקיימים.
2. כרגע הפרויקט שומר את כתובת האימייל יחד עם נתוני הפרופיל ב-`users/{uid}` והפיד קורא מסמכי משתמשים. לפני פרסום, יש להפריד מידע פרטי ל-`privateUsers/{uid}` ולשמור מידע להצגה ב-`publicProfiles/{uid}` בלבד. יש לעדכן את הקוד בהתאם.
3. הגבלת 5 שיחות בצד לקוח היא חוויית משתמש בלבד וניתנת לעקיפה. לאכיפה אמיתית יש להשתמש ב-Cloud Functions/שרת ובטרנזקציה שמחשבת שיחות יזומות; יש גם למנוע מצב שבו כמה בקשות במקביל עוקפות את המגבלה.
4. אסור להסתמך על `subscriptionStatus` שנכתב מהדפדפן כדי להעניק Pro. כרגע טופס הדמו מנסה לסמן `pro-demo`; כללי האבטחה המצורפים חוסמים שינוי סטטוס מנוי. זו התנהגות מכוונת. כדי לבדוק את טופס הדמו מול הכללים, נדרש endpoint הדגמה ייעודי או סביבת Firebase נפרדת. אין לפתוח הרשאות לכל המשתמשים.
5. תשלום אמיתי דורש ספק תשלומים ושרת/Cloud Function לאימות webhook ועדכון מנוי. אין לשמור פרטי כרטיס באתר.
6. מחיקת חשבון זו גרסה בסיסית: היא מוחקת מסמך משתמש ומוחקת את חשבון Firebase Auth, אך לא מנקה אוטומטית את כל השיחות/ההודעות/הלייקים. יש להוסיף מחיקה מתוזמנת/Cloud Function ומדיניות שמירת נתונים. Firebase עשוי לדרוש התחברות מחדש לפני מחיקת משתמש.
7. בדוק את כללי Storage לפני שימוש בהעלאת קבצים. כרגע התמונות נשמרות כנתוני base64 במסמך Firestore; הפתרון היציב לפרודקשן הוא Firebase Storage עם מגבלת גודל וסוג קובץ, ואז לשמור במסמך רק URL.
8. יש להוסיף אימות כתובת אימייל, איפוס סיסמה, הגבלת קצב, דיווח/חסימה, טיפול במשתמשים אנונימיים והסכמה משפטית לפני השקה.
9. קובץ `admin.html` הוא ממשק בלבד. יש לאמת הרשאות מנהל בצד שרת/כללים; אין לסמוך על הסתרת קישור או על קוד דפדפן.

## פרטי Firebase
הקונפיגורציה בדפדפן היא מזהה פרויקט ציבורי ולא תחליף לכללי אבטחה. מפתחות API בדפדפן בדרך כלל אינם סוד; יש להגדיר הגבלות API, Authentication ו-Firestore Rules מתאימים.

## בדיקות ידניות מומלצות
- הרשמה חדשה יוצרת משתמש Regular.
- משתמש לא מחובר מופנה לדף הכניסה.
- בדיקת גיל מתחת ל-18 נדחית בעת שמירת הפרופיל.
- בחירת תמונה מציגה preview; קובץ לא-תמונה או מעל 4MB נדחה.
- משתמש Regular לא מצליח להתחיל שיחה שישית לאחר שהכללים בצד שרת יוטמעו; עדיין יכול להשיב לשיחה קיימת.
- משתמש Pro אמיתי מקבל חותמת ויכולות Pro רק לאחר אימות תשלום בצד שרת.
- משתמש לא יכול לקרוא או לשנות מידע פרטי של משתמש אחר.
